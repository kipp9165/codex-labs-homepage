# Scroll Class Infrastructure Primer

Scroll-class infrastructure treats operational knowledge as core infrastructure, not documentation debris. This primer explains the standards that make scrolls executable and resilient. Use it to build knowledge systems that hold under scale.

## Infrastructure Criteria
- A scroll must be action-ready and role-specific.
- It must include triggers, sequence, and failure handling.
- It must remain valid across team transitions.

## Class Taxonomy
- Define classes: protocol, diagnostic, governance, and recovery.
- Assign class-specific review requirements.
- Prevent mixed-class artifacts that blur intent.

## Execution Surfaces
- Place scrolls where operators already work.
- Ensure fast retrieval during active incidents.
- Keep one canonical version per artifact.

## Reliability Standards
- Test scrolls against real execution scenarios.
- Measure adherence and outcome quality.
- Decommission artifacts that cannot be executed cleanly.

## Change Management
- Version all edits with rationale.
- Require approval for class changes.
- Communicate updates through fixed rollout rituals.

## Long Term Stewardship
- Assign class stewards with accountability.
- Audit class coverage against business risk.
- Continuously refine taxonomy as operations evolve.
